# 机会雷达 — QA 台账

只记**产品形态**的问题（需要人来定方向的）。机械缺陷当场修掉并写进 commit，不进这里。

格式：现象 → 量到的事实 → 为什么没自作主张改 → 可选方向。

## Q1 · 行业卡的「背后的催化」会被单家公司的公告盖过产业价格

**现象**：7/27「电池」板块的六段里，「背后的催化」写的是
「科达利:关于回购公司股份方案的公告」，而不是同为高档、且更贴行业层面的
「碳酸锂期货下跌 3.5%」。价格证据出现在下方证据列表里，没有丢，但不是主角。

**事实**：`narrative` 取 `catalyst.items[0]`，排序是等级优先、同级取最新。
两条都是 HIGH，公告发布时间更晚，所以公告排前面。

**为什么没改**：这是「行业卡该拿什么当主催化」的产品判断。一家成分股的回购
对整个板块的解释力，和一条产业链价格谁更强，取决于产品想让用户先看到什么——
不是我该替 sway 定的。

**可选方向**：① 行业卡的主催化优先取「行业级证据」（板块自身资讯 + 产业价格），
个股公告退到证据列表；② 六段之外单列一行「产业价格」，与催化并列；③ 维持现状。

## Q2 · 产业价格证据用户很难遇到

**现象**：站外证据（可点开的期货行情页）今天线上一条都没出现。

**事实**：20 个品种里当天够催化门槛（|涨跌| ≥1.5%）的 5–7 条，
覆盖 10 个板块；而机会雷达每天只出 3 个行业。两者相交才看得见——
2026-07-30 当天入选的银行/乘用车/航运港口都不在覆盖名单里。
7/27「电池」入选那天就能看到（已用真实组件渲染验证过，链接 HTTP 200）。

**为什么没改**：能调的三个旋钮——扩品种、降门槛（1.5%）、给价格证据更高权重——
都会改变「什么算催化」的产品定义。降门槛尤其危险：0.3% 的日内波动变成"催化"
就是把噪音包装成信息。

**可选方向**：① 扩到更多品种（当前 20 个覆盖 10 个板块，A 股 123 个可评估板块）；
② 在「市场强弱地图」里单独展示产业价格行，不受机会雷达的 3 个名额限制；
③ 维持现状，等覆盖面自然提高。

## Q3 · 信号类型徽章与链接同色

**现象**：`趋势形成 / 刚刚启动` 徽章用 brand amber，与页面上链接的颜色一致。

**事实**：真浏览器实测 `cursor: auto`（不是 pointer），且带 `title` 提示
（"资金连续流入、多数股票同步上涨，趋势已被市场确认"）。
整个机会雷达区**没有任何元素显示手型却点不动**——所以这不是坏的可点性，
只是同色带来的轻微歧义。

**为什么没改**：改配色属于设计系统的决定，`DESIGN.md` 里 amber 是品牌主色、
本来就不只给链接用。

**可选方向**：① 徽章改用更低饱和度的中性底；② 维持现状。

## Q4 · 公司名与行业词撞名时，行业稿会被算成它的催化

**现象**：「机器人(300024)」的催化里出现
「机器人奔向杭州"新考场" 有企业订单已翻番｜活力中国调研行」——
这是一篇讲整个机器人行业的媒体稿，不是这家公司的事。

**事实**：已加的规则是「媒体稿要升到高档，标题里得点名这家公司」。
这家公司的名字**就叫**「机器人」，所以行业稿的标题天然"点名"了它，规则失效。
同类：中国联通/中国石油这种名字即行业的公司。

**为什么没改**：可行的收口是维护一张"名字即通用词"的公司清单并对它们
关掉媒体升档——但那是一张需要人工维护、会随时间漂移的词表，
且误伤代价（真·公司新闻被降档）不小。属于要不要引入这类维护成本的产品选择。

**可选方向**：① 维护通用词公司名单，对其媒体证据封顶到中档；
② 要求媒体稿的标题同时出现公司名**和**股票代码才升高档（更严，会降低覆盖）；
③ 维持现状，靠证据可点开让用户自己判断。

## Q5 · 前复权四价的**日常刷新**没有可靠源（已实测，不是猜测）

**现象**：`backfill-ohlc.ts` 首轮冷跑很好——4899/5309 成功、683239 行、141 秒。
同一天再跑一次（`--minFilled=99999` 全市场刷新），**5151/5349 失败、耗时 859 秒**，
腾讯返回 `waf.tencent.com/501page`。

**事实**：腾讯 `fqkline` 不支持多标的批量（`;` 分隔被 WAF 拦），所以一次全市场刷新
= 5349 个请求。今天累计打了上万次之后就被限了。**冷启动能过、当天重复不能过**——
所以「一天一次 5349 请求是否可持续」这件事，我今天无法验证。

**为什么没放进调度器**：曾经加进 `opportunity-radar` 当第二步，实测那一轮 96% 失败
（烧 14 分钟 + 每天必响一条告警）。把一个**未经冷启动验证**的步骤放进正要开启的常驻任务，
等于把没验过的东西当成已完成——所以撤掉了。

**当前的降级路径是完整的**（不是坏的）：
· 一字板 → 四价缺失时对最终 ≤8 只候选现拉新浪 K 线兜底（旧行为，正确，≤8 个请求）；
· 机械异动 → 逐对独立选口径，缺复权价的那几对退回未复权 + 宽阈值（11pp）。
  代价是除权日会重新出现误判（首轮实测 7 只）。

**可选方向**：① 明天冷启动状态下单跑一次，确认一天一次是否可持续，可持续再进 job；
② 改用新浪 K 线做日常四价（新浪实测 5349 请求 / 96 秒稳定，但它**不前复权**——
一字板判定够用，机械异动判定不够）；③ 前复权改成**周级**回补，日常只补一字板需要的当日四价。
