# 数据源调研台账（loop 每轮追加）

**用途**：数据是解牛的命根子。这个台账记录「候选源 → 实测 → 判决 → 接入方案」的全过程，让每轮 loop 不重复劳动。

**规则**：
- 每个候选源**必须实发 HTTP 请求**才能写判决，禁止凭记忆下结论。
- 判决只有四种：`✅ 已接入` / `🟢 验证可用（待接入）` / `🟡 有条件可用（记明条件）` / `🔴 不可用（记明原因）`。
- **判决必须附评分卡** —— 按 `data-source-quality-rubric.md` 的 2 道门槛 + 8 个维度打分。未实测的维度写 `?`，**有 `?` 就不出总分**，不许拍脑袋填。
- 已判 🔴 的源**不再重复调研**，除非有明确的新线索（改版、新端点）。
- 详细请求模板（能照抄的那种）写进 `data-sources.md`；这里只记结论 + 一行要点。

**评分卡**：`data-source-quality-rubric.md` —— A 权源等级 18 / T 时效性 16 / U 独家增量 14 / S 可挂载性 12 / C 覆盖率 12 / N 信噪比 11 / F 保真度 10 / H 历史深度 7；外加 G1 合规、G2 可用性两道硬门槛。

### Run 1 — 2026-07-24 10:56 CST · 目标：给已接入源建评分基线（第一批 3 个 + 1 个意外）

**候选**：巨潮资讯·公告 / 东财·快讯 / 华尔街见闻·A股（＋健康检查顺带查了集微网）

#### 实测证据

**G2 可用性**（间隔 3s 连打 10 次）
- 东财快讯 `np-weblist`：10/10，p95 121ms，中位 35ms
- 华尔街见闻 `api.wallstreetcn.com`：10/10，p95 425ms，中位 223ms
- 巨潮 `hisAnnouncement`：10/10，p95 139ms，中位 94ms
  - ⚠️ **首测 0/10 是我自己的错**：orgId 我拍脑袋填了 `9900023324`，实际 688981 的 orgId 是 `gshk0000981`。接口照返 HTTP 200 + `announcements: []`，**不报错**。→ 教训写进下面「坑」。

**T 时效性**（隔 ~13 分钟抓两次）
- 东财快讯：最新条 `showTime` 距抓取时刻 **159s**；二次抓取 30 条里 **20 条是新的** → 活流，T=4
- 华尔街见闻：最新条距今 **50s**；同样 20/30 新 → 活流，T=5
- 巨潮：**测不了**，原因见下条 F

**F 保真度 — 巨潮 `announcementTime` 只有日期精度**
- 定向查 688981 近 2 个月：**20/20 条都是 `00:00:00`**
- 全市场 szse 2026-07-24：**82/90 条是 `00:00:00`（91%）**，只有 ~9% 带真实时分秒（如 `07:48:05`）
- 对照实验排除了「定向查丢精度」的猜想：同一条公告（`adjunctUrl` 匹配）在全市场查和定向查里**时间戳完全一致**（都是 07:48:05）→ 是**公告本身**分两类，不是查询方式的锅
- `storageTime` 字段全为 `null`，指望不上
- **实际影响（已在库里印证）**：`cninfo-announcement` 与 `eastmoney-announcement` 的「最新发布距今」都卡在 **10.9h** —— 正是当天 00:00 CST 到查询时刻的间隔。在按时间倒序的流里，**今早 8 点发的公告被打成今天 00:00，会沉到当天所有快讯下面**；PRIMARY 一手内容被 MEDIA 压住。

**U 独家增量**（100 条 × `normalizeTitle` 比库）
- 第一次测法**错了**：拿全库比，东财快讯只有 15%、华尔街见闻只有 4% —— 但库里本来就装着这两个源自己的历史，测出来的是「距上次抓取的新鲜度」，不是独家度
- **修正测法（排除该源自身的行）**：东财快讯 **97/100 独有**（对比其它源 13,308 条）；华尔街见闻 **97/100 独有**（对比 22,508 条）→ 两者 U=5
- ⚠️ 局限：`normalizeTitle` 只抓字面重复，**语义重复（同一事件不同措辞）抓不到**，真实重合度应高于此

**N 信噪比**（100 条真实数据喂 `screenQuality()` + `relevance.ts` 全套）
- 东财快讯：**96/100 通过**，拦截 `{etf-marketing:1, roundup:3}`
- 华尔街见闻：**91/100 通过**，拦截 `{roundup:9}`

⚠️ **修 bug 时的陷阱**（实测过，别踩）：
```js
new Date("2026-07-24 11:43:04:552")   // ✅ 2026-07-24T03:43:04.552Z（V8 容忍空格式）
```

毫秒前是**冒号**不是点。别顺手把空格换成 `T` 去「规范化」，那正好会触发和集微网一模一样的兜底 bug。另外空格式按**本机时区**解析——本机是 CST 所以现在对，但换 UTC 机器就整体偏 8 小时，稳妥写法是显式补 `+08:00`。
