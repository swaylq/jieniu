# 数据源质量评分卡（Data Source Quality Rubric）

**为什么要它**：数据是解牛的命根子，但「这个源好不好」以前全靠感觉。感觉不可比、不可复现、会腐坏。这份评分卡把它拆成 **2 道硬门槛 + 8 个可实测维度**，每个维度都有明确的测量配方——**分数必须来自实发请求，不许凭印象打**。

**谁用**：数据源调研 loop 每轮对候选源打分；已接入源每季度复评一次（源会腐坏，见 §6）。

---

## 一、两道硬门槛（Gate，不打分，不过直接降级）

门槛不是维度——它们是否决项。一个 95 分的源踩了 G1 照样不能接。

### G1 · 合规与封禁风险

| 判定 | 结果 |
|---|---|
| 需要破解签名/验证码，或 robots 明确 `Disallow` 目标路径，或需绕过付费墙 | 🔴 **否决** |
| 有频率限制但可通过节流/缓存合规满足 | 🟡 通过，方案里必须写明节流参数 |
| 公开无鉴权，或 robots 显式放行 | ✅ 通过 |

**测法**：拉 `/robots.txt` 看目标路径；看是否需要签名/登录态；查 ToS 有无禁止自动化条款。

> 例：集微网 JSON `/api/` 有 MD5 签名 + robots `Disallow:/api` → G1 否决；但它的 RSS `/api/rss/hbb` 是公开投喂路径 → 通过。**同一个站，不同路径，门槛结论可以相反。**

### G2 · 可用性

**测法**：间隔 3 秒连打 **10 次**，记录成功率与 p95 延迟。

| 成功率 | p95 | 结果 |
|---|---|---|
| ≥ 95% | < 3s | ✅ 通过 |
| ≥ 90% | < 8s | 🟡 通过，方案必须写降级/重试策略 |
| < 90% 或频繁超时 | — | 🔴 否决（除非它是不可替代的一手源，则降级为「尽力而为」旁路，不进主管线） |

## 二、8 个评分维度（0–5 分 × 权重 = 100）

| # | 维度 | 权重 | 一句话 |
|---|---|---|---|
| A | 权源等级 Authority | 18 | 离事实原点多远 |
| T | 时效性 Timeliness | 16 | 事件发生到你能看见，隔多久 |
| U | 独家增量 Uniqueness | 14 | 接了它，库里能多出多少东西 |
| S | 可挂载性 Structure | 12 | 能不能准确挂到具体个股 |
| C | 覆盖率 Coverage | 12 | 覆盖股池里它管得着几只 |
| N | 信噪比 Signal/Noise | 11 | 抓 100 条，有几条配进 feed |
| F | 保真度 Fidelity | 10 | 转述过程中有没有失真 |
| H | 历史深度 History | 7 | 能往回翻多久 |

权重取向说明：**A + F = 28 分给「真实性」**，因为金融产品里一条错信息的代价远大于漏一条；**T = 16 分给「实时性」**；**U = 14** 是因为跟已有源 90% 重合的源接了等于白接（还平白增加去重负担），这一条最容易被低估。

---

### A · 权源等级 Authority（权重 18）— 真实性的「上游」维度

离事实原点有多远。这一条**不是打请求能测出来的**，但必须有证据（域名归属 / 是否法定披露平台 / 是否持牌 / 内容署名）。

| 分 | 判据 | 例 |
|---|---|---|
| 5 | 法定披露：有法律责任的原文 | 巨潮公告、交易所公告、证监会处罚决定、公司定期报告 |
| 4 | 官方准一手：主体自己说的，但非法定文书 | 互动易董秘答、上证 e 互动、业绩说明会/路演纪要、公司官网 IR |
| 3 | 持牌媒体原创首报 / 署名卖方研报 | 财联社电报、华尔街见闻原创、集微网原创、券商研报 |
| 2 | 持牌媒体转载/编译/综述 | 各类「XX 日报」「早间要闻」 |
| 1 | 非持牌自媒体原创 | 行业公众号原创 |
| 0 | UGC / 论坛 / 传闻 | 股吧、雪球评论 |

> **陷阱**：不要看域名大小看等级。「半导体行业观察」「与非网」体量不小，但内容以洗稿/编译/转载为主 → 判 2 不判 3。反过来，一个小站如果是原创首报，就该给 3。

### T · 时效性 Timeliness（权重 16）— 实时性

分两种测法，按源的体裁选：

**a) 公告/披露类** — 对账法：取该源最近 20 条，与巨潮 `announcementTime` 逐条比对同一份公告的时间戳，取**延迟中位数**。

**b) 快讯/媒体类** — 新鲜度法：间隔 10 分钟抓两次，记录「最新一条的时间戳距抓取时刻多久」，取两次的中位数；同时确认第二次抓到了第一次没有的新条目（证明它是活的流，不是静态缓存）。

| 分 | 延迟 |
|---|---|
| 5 | ≤ 60 秒（准实时） |
| 4 | ≤ 5 分钟 |
| 3 | ≤ 30 分钟 |
| 2 | ≤ 4 小时（当日可见） |
| 1 | T+1 |
| 0 | 更慢 / 不可预测 |

> **注意区分两种延迟**：源自身的首发延迟（这一条测的）vs 我们 poll 频率带来的延迟（那是我们的实现问题，不算在源头上）。方案里要分别写清楚。

### U · 独家增量 Uniqueness（权重 14）

**测法**（硬指标，能真跑）：拉该源最近 100 条，用现有 `dedupe.ts` 的 `normalizeTitle` + `crossSourceKey` 与库里已有 NewsItem 比对，算 **新增率 = 未命中条数 / 总条数**。

> ⚠️ **已接入源必须排除该源自身的历史行**（`sourceId: { not: 自己 }`）。否则库里装着它自己的产出，测出来的是「距上次抓取的新鲜度」而不是独家度——run 1 踩过：东财快讯不排除自身测出 15%，排除后是 **97%**，差了 6 倍，结论完全相反。
>
> ⚠️ **`normalizeTitle` 只抓字面重复**，同一事件不同措辞的语义重复抓不到，所以这个数是**独家度的上界**。判 5 分时要在台账里写明这个局限。

| 分 | 新增率 |
|---|---|
| 5 | ≥ 70%（基本是新东西） |
| 4 | 50–69% |
| 3 | 30–49% |
| 2 | 15–29% |
| 1 | 5–14% |
| 0 | < 5%（纯重复，接了只会增加去重负担） |

> 得低分不必然否决——如果它是**更快**拿到同样内容的源（T=5 而现有源 T=3），它的价值在时效不在增量，方案里要说明它是「抢跑源」而非「增量源」。

### S · 可挂载性 Structure（权重 12）

决定「能不能准确挂到具体个股」——挂错比不挂更糟（研报绑板块那次教训，见 `types.ts:subjectOnly` 注释）。

| 分 | 返回结构 |
|---|---|
| 5 | 自带规范股票代码 + 事件类型（如华尔街见闻 `symbols[]` = `688981.SS`） |
| 4 | 自带规范股票代码 |
| 3 | 自带公司全称/简称（需词典映射） |
| 2 | 无结构化字段，需正文 NER 抽取 |
| 1 | 仅标题可匹配 |
| 0 | 无法可靠挂载到个股 |

### C · 覆盖率 Coverage（权重 12）

**测法**：拉该源 7 天数据，对 hot-universe（15 板块 / 128 股）算两个数：
- **股票覆盖率** = 出现过的股数 / 128
- **漏报率**（仅公告类）= 巨潮同期该股池公告数中该源没有的比例

| 分 | 股票覆盖率（媒体类）/ 漏报率（公告类） |
|---|---|
| 5 | ≥ 80% / 漏报 ≤ 2% |
| 4 | 60–79% / 漏报 ≤ 5% |
| 3 | 40–59% / 漏报 ≤ 15% |
| 2 | 20–39% / 漏报 ≤ 30% |
| 1 | 5–19% |
| 0 | < 5% |

> **垂直源豁免**：只覆盖单一板块的源（如集微网只管半导体）按**其目标板块内**的覆盖率打分，并在评分卡上标 `[垂直:半导体]`。拿全市场分母去衡量垂直源是错的。

### N · 信噪比 Signal/Noise（权重 11）

**测法**（硬指标）：把该源 100 条真实数据喂现有管线 `screenQuality()` + `relevance.ts` 全套过滤器，算**通过率**。

| 分 | 通过率 |
|---|---|
| 5 | ≥ 70% |
| 4 | 50–69% |
| 3 | 35–49% |
| 2 | 20–34% |
| 1 | 10–19% |
| 0 | < 10%（噪音源，接了就是给去重管线上刑） |

### F · 保真度 Fidelity（权重 10）— 真实性的「下游」维度

权源等级高不代表这个**接口**给的数据准。抽 10 条与权威原文逐条比对：

检查项：① 标题是否被改写/标题党　② 正文是否截断或缺失　③ **数字是否失真**（金额、比例、日期）　④ 时间戳是否正确（不是抓取时间冒充发布时间）　⑤ 股票代码是否挂错

| 分 | 结果 |
|---|---|
| 5 | 10/10 完全一致 |
| 4 | 9/10，偏差不涉及数字与时间 |
| 3 | 8/10，或普遍截断但可接受 |
| 2 | 6–7/10，或时间戳系统性偏移 |
| 1 | ≤ 5/10 |
| 0 | 出现数字失真或代码挂错 → **同时触发 G1 复审**（错误金融信息不可接受） |

> **时间戳冒充是最常见的坑**：不少接口返回的是「入库时间」而非「发布时间」，会把一条三天前的公告显示成刚刚。必须抽查验证。

> ⚠️ **F 要分两层打：源的保真度 vs 我们实现的保真度。** 评分卡的 F 分给**源**；但同一次抽查往往会顺带暴露我们自己解析器的失真，那属于 bug 不属于源的分数，要单独记成 P1。
>
> run 1 实例：集微网 feed 的 `pubDate` 完全正确（源 F=5），但生产 `parseJiweiRss` 漏调 `cdata()`，`new Date("<![CDATA[...]]>")` 解析失败后兜底成 `new Date()`——**10/10 条 `publishedAt` 变成抓取时刻**，库内 12/12 条 `publishedAt ≈ createdAt`。台账写法：`F | 源5/实现0`。
>
> **实现层保真度的快速探针**：查库里该源的 `publishedAt` 与 `createdAt` 之差。大批量趋近 0 就是解析器在兜底，不是源在实时推。

### H · 历史深度 History（权重 7）

**测法**：往回翻页，看最早能拉到哪天。对一年回填（`docs/specs/2026-07-23-one-year-backfill.md`）和 thesis 建模有直接影响。

| 分 | 可回溯 |
|---|---|
| 5 | ≥ 3 年 | 4 | ≥ 1 年 | 3 | ≥ 6 个月 |
| 2 | ≥ 1 个月 | 1 | ≥ 7 天 | 0 | 仅当下滚动窗口 |

## 三、总分 → 处置决策

总分 = Σ(维度分 × 权重) / 5，满分 100。

| 分档 | 等级 | 处置 |
|---|---|---|
| ≥ 80 | **A · 核心源** | 进主管线，高频抓（≤5 分钟），`tier` 按 A 维度定，可进提醒 |
| 65–79 | **B · 补充源** | 接入，中频抓（15–60 分钟），importance 不加成 |
| 50–64 | **C · 边缘源** | 只在特定场景接（限定板块/事件类型），低频抓，默认不进提醒 |
| < 50 | **D · 不接** | 记入台账 🔴，写明原因，不再重复调研 |

**分数 → 现有字段的映射**（让评分真的落到代码里）：
- `SourceTier`：A 维度 ≥4 → `PRIMARY`；A = 3 → `MEDIA`；A ≤ 2 → `DERIVED`
- 抓取频率：按总分档位（上表）
- `subjectOnly`：S 维度 ≥4 时置 `true`（源已给出权威主体，不要再做标题文本匹配）
- 提醒资格：总分 ≥80 **且** F ≥4 才允许触发用户提醒

## 四、评分卡记录格式

每个源评完在台账 `data-source-research-log.md` 记一行：

```
| 源 | A | T | U | S | C | N | F | H | 总分 | 等级 | G1 | G2 | 测于 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 深交所互动易 | 4 | 3 | 5 | 4 | ? | ? | ? | ? | — | — | ✅ | ✅ | 2026-07-24 |
```

**未实测的维度写 `?`，不许拍脑袋填。** 有 `?` 就不出总分——宁可留空，不要给一个假精确的数。

## 六、腐坏与复评

**源会腐坏**，而且是静默腐坏——改版、加签名、字段改名、限流收紧，接口还返回 200，内容却空了或变了。历史上已经吃过：财联社改版、cninfo RSSHub 路由下线、沪市 PDF 加 JS 挑战。

规则：
1. **已接入源每季度全量复评一次**，重跑 8 个维度。
2. **loop 每轮轮换健康检查 1 个已接入源**（轻量版：打通 + 条数不为 0 + 最新条时间戳新鲜 + 抽 1 条比对保真）。
3. 任何维度**跌 2 分以上**立刻记台账并提出处置建议。
4. **HTTP 200 不等于健康**——必须校验条数、时间戳新鲜度、关键字段非空。只看状态码是历史上翻车最多的地方（见 `evolution/lessons.md`）。

## 七、数据类源变体（提案 · run 3 由行情源逼出，待 sway 拍板）

**问题**：本卡的 8 维是为**新闻/文本源**设计的。`U 独家增量`（比 NewsEvent 去重）和 `N 信噪比`（过 `screenQuality`/`relevance` 管线）**只对新闻有意义**。纯数字源（行情、财务、资金流、价格指数、宏观序列）根本不进那条管线，硬套只能填 N/A，导致算不出可比总分。

**先判定源的类型，再选卡**：
- **文本类**（公告 / 快讯 / 研报 / 问答 / 媒体报道）→ 用正卡（§二）
- **数据类**（行情 / 估值 / 财务 / 资金流 / 价格指数 / 宏观高频）→ 用下面的变体

**数据类变体权重**（把新闻专属的 U14+N11=25 分，重分配给数据源真正的质量轴）：

| 维度 | 权重 | 数据类含义 | 测法 |
|---|---|---|---|
| A 权源 | 18 | 离交易所/披露原点多远 | 是否交易所自有 feed / 持牌再分发 |
| T 时效 | 16 | 行情延迟 / 数据更新滞后 | 响应内时间戳距真实时刻 |
| **完整性** | **18** | 字段齐全度 + 覆盖标的比例 | 目标字段非空率 × 标的覆盖率（吸收原 U） |
| S 可挂载 | 12 | 能否精确挂到标的 | 按 ticker 派生=天然满分 |
| C 覆盖 | 12 | 覆盖股池比例 | 对 hot-universe 有效返回率 |
| **一致性** | **14** | 多源交叉一致 / 异常值率 | 双源逐笔比对一致率（吸收原 N） |
| F 保真 | 10 | 数字是否准 | 抽样对权威值，数字级比对 |
| H 历史 | 7 | 可回溯多久 | 翻到最早数据点 |

**已用此变体评的源**：
- **行情（新浪+腾讯）** = A3 T5 完整性4(缺估值) S5 C5 一致性5 F5 H5 ≈ **86 分 · A 级核心源**。估值腾讯兜底修好后完整性→5，逼近满分。

> 数据类源的 F 是**可硬验证**的（数字对得上就是对），这是它相对新闻源的结构性优势——新闻的 F 只能抽样看有没有改写/截断，数据的 F 能逐笔精确核。

## 八、处置修正：关联广度（Relevance Breadth）· run 5 由产业链价格逼出

**问题**：评分卡量的是**单条数据的质量**，不是**这个源和你股池的相关广度**。一个各维度都近满分的源，可能只对你 1/4 的股池相关——高质量 ≠ 高接入优先级。

**实例**：产业链价格（新浪期货）质量分 ~88（A4 T5 F4 完整性5 都很高），但期货只覆盖材料驱动型板块（光伏/锂电/新能源/汽车/有色 ≈ 4/15 热门板块），对 AI/算力/半导体/光模块/机器人/医药/白酒/银行/券商完全无关。按分该 A 级，按相关广度只配定向接入。

**规则**（处置层门控，不进 0–5 打分）：出总分后，再判**关联广度**决定处置：
- **广谱**（覆盖股池 >60%，如资金面覆盖 96%）→ 按总分定级，A 级优先接
- **利基**（只对特定板块/事件相关，如产业链价格）→ **无论总分多高，降为「定向接入」**：只对相关板块/thesis 启用，不当通用源，抓取与展示都限定范围
- 判断依据：这个源产出的数据，能挂到股池里多大比例的股 / 多少个板块

> 一句话：**总分回答「这数据好不好」，关联广度回答「值不值得为它加一套管线」。** 两个都要过，才进主管线。
