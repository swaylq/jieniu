# 机会雷达 — 缺失数据补全方案

2026-07-31 设计。**每一条的数据源都在写方案时实测过**（不是照文档想象），
实测命令与结果附在各条下面。没验证过的一律标「待摸源」，不写进可排期的部分。

原则沿用上一轮的教训：**先证明拿得到，再谈算法**。判据描述的是需求，
数据可得性才是前提。

---

## 零、先纠正一条：「151 只取不到历史」不是缺口

首轮交付里我把回填的 `failed=151` 报成了数据缺口。诊断下来它不是：

| 类别 | 只数 | 该不该补 |
|---|---|---|
| 退市 / ST / 老壳（东方明珠 600832、琼民源A、PT水仙…） | ~145 | **不补**，基础过滤本来就排除 |
| 美股实体（NVDA、LI…） | 计入上行 | **不补**，A 股行情源本就没有 |
| 北交所 + 主板新股（920178、920096…上市不足 50 个交易日） | ~42 | **不用补**，会随时间自愈 |

北交所整体 **334 只、平均 127 天历史**，新浪 `MoneyFlow` 对 `bj` 前缀正常返回
（实测 bj920118 / bj430047 / bj830799 各取回 140 行），**没有源限制**。

> 结论：这一项**零工作量**。真正的缺口是下面三类。

## 一、P0 — 已验证可取，直接排期

### P0-1 前复权 OHLC（腾讯 `fqkline`）

**现状**：`MarketDaily` 只有 `close`（未复权）。因此
① 回测阶段做不了一字板剔除（每天几十次外网请求不现实）→ 回测结果略微高估；
② 连续涨停只能用收盘价推算，遇到停牌/除权会误判；
③ 展示「N 日前的价格」用的是未复权价。

**验证**（2026-07-31 实测）：
```
https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600519,day,,,320,qfq
→ {"code":0,"data":{"sh600519":{"qfqday":[["2026-07-17","1269.010","1253.000","1269.330","1238.980","58417.000"],…]}}}
   [日期, 开, 收, 高, 低, 成交量]，一次可取 320 根，**已前复权**
```

**方案**：`MarketDaily` 加 4 列 `open / high / low / adjClose`（全部 nullable，
不影响既有行）。新脚本 `backfill-ohlc.ts`，与 `backfill-market-daily.ts` 同形
（有界分片 + 幂等 + 按缺口排序）。日常只补增量（`--days=8`）。

**解锁**：一字板/连续涨停在**回测里也能剔除**（回测口径与线上一致）；
`priceGapAnomaly` 从「>11% 跳变」这种粗判据升级为「复权前后不一致」的精确判据。

**成本**：全市场一次约 5300 请求，按现有并发 8 估 ~3 分钟；日常增量 <1 分钟。
Schema 只加列不改约束。

### P0-2 产业链商品价格：2 → 20 个品种

**现状**：`src/server/ingest/signals.ts` 的 `COMMODITY_MAP` **只硬编码了 2 条**
（碳酸锂→新能源、多晶硅→光伏），所以库里 `EntitySignal(kind="commodity")` 只有 2 行。
管线本身是好的，缺的只是覆盖面。这直接导致行业级「中」档催化几乎无料，
而催化质量在行业机会分里占 10%。

**验证**（2026-07-31 实测 `hq.sinajs.cn/list=`，**20/20 全部返回**）：

| 符号 | 品种 | 可挂板块（库里真实存在，括号内为成分股数） |
|---|---|---|
| `nf_CU0` | 铜 | 工业金属(57) |
| `nf_AL0` | 铝 | 工业金属(57) |
| `nf_RB0` | 螺纹钢 | 普钢(22) |
| `nf_I0` | 铁矿石 | 普钢(22) |
| `nf_JM0` | 焦煤 | 焦炭(7) / 煤炭开采(26) |
| `nf_TA0` | PTA | 化学原料(58) |
| `nf_MA0` | 甲醇 | 化学制品(178) |
| `nf_PP0` | 聚丙烯 | 塑料(76) |
| `nf_SA0` | 纯碱 | 化学制品(178) |
| `nf_FG0` | 玻璃 | 玻璃玻纤(15) |
| `nf_SI0` | 工业硅 | 光伏设备(65) |
| `nf_NI0` | 镍 | 能源金属(11) |
| `nf_AG0`/`nf_AU0` | 白银/黄金 | 贵金属(13) |
| `nf_C0` | 玉米 | 饲料(17) |
| `nf_M0` | 豆粕 | 饲料(17) / 养殖业(21) |
| `nf_SC0` | 原油 | 炼化及贸易(29) / 油气开采(4) |
| `nf_PG0` | 液化石油气 | 燃气(29) |
| `nf_LC0` | 碳酸锂 | 电池(101) |
| `nf_PS0` | 多晶硅 | 光伏设备(65) |

候选 30 个板块名里 **27 个在库里真实存在**（只有「钢铁 / 化纤 / 石油石化」这三个
是我按行业习惯写的、库里用的是「普钢 / 化学纤维口径不同 / 炼化及贸易」）。

**一个要注意的约束**：`EntitySignal` 的唯一键是 `(entityId, kind)`，
所以**一个板块只能挂一条 commodity 信号**（这也是原注释里「一板块一代表品种」的由来）。
一个板块对应多个品种时（化学制品 ← 甲醇 + 纯碱），方案是：
主品种进 `label` 与 `numValue`，其余品种放进 `detail.others[]`，不新增表。

**解锁**：行业级催化从「几乎总是 NONE」变成每天有料；
`sectorOpportunityScore` 里 10% 的催化项开始起作用；
用户卡片的「背后的催化」不再频繁落到「暂无明确催化」。

**成本**：改一个常量数组 + `detail.others` 的读写，**半天以内**。

### P0-3 研报回填（东财 `reportapi`）

**现状**：研报覆盖率约 29.5%，「低」档催化不完整。

**验证**（2026-07-31 实测）：
```
https://reportapi.eastmoney.com/report/list?industryCode=*&pageSize=3&beginTime=2026-07-01&endTime=2026-07-31&pageNo=1&qType=0
→ {"hits":376,"data":[{"title":"…","stockName":"京基智农","stockCode":"000048",
    "orgSName":"华鑫证券","publishDate":"2026-07-31","predictNextTwoYearEps":"1.91",…}]}
```
**注意这是 `reportapi.eastmoney.com`，与被封的 `push2.eastmoney.com` 不同族**——
同族的 `datacenter-web.eastmoney.com` 今天也实测正常（`RPT_INDUSTRY_INDEX` 返回 88210 页）。
封锁只针对 `push2*`。

**方案**：新增一条 source 走既有 ingest runner，置 `subjectOnly: true`
（主体由 `stockCode` 权威给出，跳过综述启发式——这是既有教训里踩过的坑）。
`predictNextTwoYearEps` 顺带补进一致预期。

**解锁**：催化的「低」档完整；一致预期覆盖率提升；
研报本身作为事件进入个股页的事件流（既有能力，只是缺料）。

**成本**：一条 source 定义 + 解析器 + 测试，**一天以内**。

## 二、P1 — 需要先做一步验证工作

### P1-1 主力资金的置信度标注（两源交叉）

**现状**：主力资金是按成交单笔金额分档的**估算**，回测实测次日反转率 51%–55%
（逆势走强那一桶 71%）。目前的设计约束是「资金不能单独决定入选」，是对的，
但**噪音水平没有被量化进评分**。

**已验证**：腾讯 `qt.gtimg.cn/q=ff_sh600519` 今天返回 `v_pv_none_match="1"`，
即**该接口已不可用**。东财 `push2` 在封锁期。所以短期内可能只有新浪单源。

**方案（分两步，第二步取决于第一步）**：
1. 先做**自洽性校验**（单源也能做）：同一天的 `netAmount / netRatio / amount`
   三者应满足 `netAmount ≈ netRatio × amount`，偏差超阈值即标记该行 `suspect`；
   再用「当日涨跌幅与资金方向长期背离」的统计给每只股一个稳定性分。
2. 待东财解封后补第二源，做**跨源一致性**打分。

**解锁**：`MarketDaily` 加 `confidence`，低置信度的行在资金强度里降权，
而不是像现在这样一视同仁。

**成本**：第一步半天；第二步取决于封锁何时解除，**不排期**。

### P1-2 行业景气指标（东财 datacenter-web）

**已验证**：`datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_INDUSTRY_INDEX`
可用，返回行业指标时间序列。**但 `reportName` 的完整清单我没有摸清**——
猜 reportName 正是我上一轮写进教训里的「不得猜脚本名/字段/数据源」。

**方案**：先做一次**摸源**（半天）：抓 `data.eastmoney.com` 的行业数据页，
从前端请求里把真实的 `reportName` + 字段名录下来，形成一张已验证清单，
再据此排期。**在摸源完成前不承诺解锁什么。**

### P1-3 信号快照累积 + 滚动回测

**现状**：逆势走强的回测样本只有 14 条，不足以下结论；
需求 §12 要求「用滚动历史调阈值」，而我们只有单一下行区间的样本。

**方案**：给 `opportunity-radar` job 加第三步——每天跑一次
`radar-backtest --days=5`，把分类型指标写进 `JobRun.metrics`，
用既有的 `baselineChecks`（与上一次成功运行比、只在变坏时告警）盯住效果漂移。
积累到每类 ≥100 条、且跨过一段上行区间后，再谈调阈值。

**成本**：job 加一步 + 指标落库，半天。**但要等时间**——这是唯一一条
「不是工程量问题，是样本量问题」的缺口。

## 三、P2 — 需要预算才能做

| 缺口 | 唯一可靠来源 | 影响 |
|---|---|---|
| 行业销量 / 开工率 / 渠道库存 | Wind、同花顺 iFinD、百川盈孚、隆众（均付费） | 「中」档催化里的「行业销量、渠道数据」这一支目前只能靠媒体转述 |
| 真实主力资金（Level-2 逐笔） | 券商 Level-2 授权 | 现在的估算口径噪音大，前台已注明但无法消除 |
| 龙虎榜席位归属（游资/机构画像） | 付费数据商 | 现有龙虎榜只有金额，判不出资金性质 |

**建议**：在拿到预算之前，不要在产品上做任何依赖这三类数据的承诺。
现有设计已经把它们排除在必需路径之外（催化可以为 NONE，卡片照样成立）。

## 四、排期建议

| 顺序 | 项 | 工作量 | 解锁什么 |
|---|---|---|---|
| 1 | P0-2 商品价格 2→20 | 半天 | 行业催化从「几乎没有」到「每天有」——**性价比最高** |
| 2 | P0-1 前复权 OHLC | 半天 | 回测与线上口径一致；一字板/连涨判定精确 |
| 3 | P0-3 研报回填 | 一天 | 催化低档完整 + 一致预期覆盖率 |
| 4 | P1-3 滚动回测 | 半天 + 等样本 | 阈值调整第一次有依据 |
| 5 | P1-1 资金自洽性校验 | 半天 | 资金噪音进入评分 |
| 6 | P1-2 行业景气摸源 | 半天摸源 | 摸完再排 |

P0 三项加起来约**两天**，做完之后机会雷达的催化维度会从「结构齐全但常年缺料」
变成「有稳定供给」。这也是当前**唯一**在拖后腿的维度——价格、资金、广度、
拥挤四个维度的数据已经齐了。
