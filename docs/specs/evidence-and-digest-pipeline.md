# 证据标准 + 复盘六步管线（张楚寒 2026-07-30 反馈）

三条反馈，三条改动。原话与对应改法：

## ① 「这些『最新证据』很多并不是真正的证据，和投资命题也没有完全对应上」

他圈了三条，正好是三种坏形状：

| 投资命题 | 当前所谓证据 | 实际问题 |
|---|---|---|
| 行业景气 | 研报强调公司GPU领军地位 | 只能证明券商看好公司地位，不能证明行业需求增强 |
| 公司治理 | 重大资产重组「通常」涉及战略调整 | 是通用推测，不是摩尔线程发生了什么 |
| 毛利率 | 净利润预增「可能」反映毛利率改善 | 净利润也可能来自收入增长、费用下降或非经常损益 |

**判据层** `src/lib/evidence.ts`（纯规则、可测）：

- `isOpinionSource` — 券商观点只能验证「市场预期」类命题（`dimensionFamily === expectation`）
- `isGenericSpeculation` — 通论（通常/往往）、模糊连词+推演动词（可能…反映）、表态套话（显示…信心）、自认无内容（未披露具体内容且无数字）
- `isInferenceChain` — 「A 表明 B」这类由事实推演出结论
- `METRIC_REQUIRED` — 命题盯哪个指标，证据里就得有那个指标。**满足任意一族即可**（「现金流与资本开支」既可由现金也可由资本开支满足；第一版逐族否决，把回购 1.03 亿判进产能族）
- `isRoundupGenre` — 早报/榜单里讲**别家公司**的事不算这家的证据；讲这家的封顶 `supporting`

分级 `direct`（本公司事实）/ `supporting`（旁证）/ `inference`（推测，不展示）。

**三处接线**：
- 写入端 `backfill-signals.ts` / `classify-signals.ts`：不合格一条都不入库，判废理由逐类计数打日志
- 读取端 `entity.thesisSignals`：`qualifyStoredSignal` 现判旧行 → 存量立刻按新标准过滤，不用等回填
- 生成端 `SIGNAL_SYSTEM`：输出从「一句自由发挥的 note」改成 `{fact, why}`，why 必须写局限

**实测**（2026-07-30）：存量 401 条只有 24.7% 合格。新提示词 80 条资讯 → 19 条有证据 → 判废 5 → 入库 15。

### 两个只有真实数据能暴露的坑

1. **喂进去的是法务套话**。A 股公告 `summary` 是正文前 128 字，恒定是「本公司董事会及全体董事保证…」。
   「大普微 2026 半年度业绩预告」(importance 85、PRIMARY) 因此产出 0 条证据——模型手上一个数字都没有，
   返回 `[]` 是**正确行为**。接上既有的 `filingExcerpt`（`evidenceBody()`）后同一条给出了「扣非净利 119,500～134,500 万元」。
2. **回填默认跳过已分类的新闻**，而张楚寒看到的假证据**全在已分类里**。不带 `--redo-legacy` 时
   回填只啃剩下的边角料（实测 60/60 条模型返回空），一条也修不到问题现场。

## ② 「点击整条『最新证据』，在右侧打开一个证据抽屉」

`evidence-drawer.tsx` + `evidence-detail.ts`。三段照他给的样例：**客观事实 / 为什么能验证该命题 / 影响判断**。
「影响判断」不需要新数据——就是同一条资讯在这家公司各命题上的全部信号，没命中的显式写「尚未验证」。
底部「查看原文」是站内 `/news/<id>`，不外链（他：跳外站会打断阅读）。

**必须 portal 到 body**：页面外层 `.jn-page-in` 的入场动画用 `animation: … both`，末帧 `transform: none`
以**单位矩阵**留在计算样式里，给后代的 `position: fixed` 造了 containing block ——
抽屉 `inset-0` 量成整页高度（实测 aside 11197px），底部按钮被顶到折叠线以下。

## ③ 「现在看起来像『抓到几条新闻，然后让模型总结』」

`src/lib/digest-pipeline.ts` —— 第 1–5 步**全部纯规则、零 AI**：

1. **候选池** `gatherEventPool`：近 30h、importance ≥ 25、扫 3000 条 → 实测约 2100 条候选
2. **去重合并** `mergeEvents`：二元组**包含率** ≥ 0.72 + 主体一致。用包含率不用 Jaccard——
   跨源重复两条长度常差一倍，实测 Jaccard 0.452 / 包含率 0.792
3. **六类分类** `categorize`：全球市场 / 国内宏观 / 行业 / 公司 / 资金 / 日历
4. **遗漏检查** `coverageReport`：每类报「池子多少 / 选中几条」，有料却没选中标 `gap`
5. **选 15–25** `selectEvents`：每类保底 3、上限 8、**同主体上限 2**
6. 强模型只跑这一次（`llmChat(..., { tier: "strong" })`）

排序按他给的六条判据，每条**单独记账**（`ScoredEvent.reasons`）：市场影响程度 / 与当日涨跌的解释力 /
信息新鲜度 / 来源可靠性 / 与用户持仓的相关度 / 是否改变原有投资逻辑。

### 三个只有跑真库才暴露的分类错误

- **摘要改判**：`classifyScope` 标题判不出时会拿「标题+摘要」再判，于是摘要里一个「私募」
  就把「宁德时代关联企业参设并购基金」拽进国内宏观——第一版国内宏观 6 条**全是公司事件**。
  改成「标题级 → 公司绑定 → 摘要级」，中间夹一道公司绑定。
- **场所词**：「中际旭创港股上市首日」因为「港股」被归全球市场。剥掉场所词后还剩不剩海外信号，
  剥完没了就说明命中的只是「在哪儿上市」。
- **连续追更**：公司类 8 个位置有 6 个是「兆易创新朱一明套现44亿后增持回购」的不同写法。
  措辞和数字都不一样，标题相似度收不住，只有主体一样 → `perSubjectCap`。

### 成本

张楚寒：「便宜模型负责分类、聚类和打标，较强模型只负责最终 15—25 条卡片和总判断」。
解牛比这更省一档——分类/聚类/打标是**纯规则**（零 token、确定性、可单测），只剩两档模型：
`OPENROUTER_MODEL`（默认，跑所有常规调用）与 `OPENROUTER_MODEL_STRONG`（只给复盘成文）。
后者没配就退回前者，不会因为漏配环境变量而静默变贵或变差。

**效果**：driver 从 6 条 → 22 条（提示词里把条数写死成事件清单条数，否则模型会把筛选再做一遍）。

## 遗留

- `rankMacroCandidates`（`macro-relevance.ts`）在复盘链路里已被管线取代，只剩自己的单测在用；
  同文件的 `marketRelevanceScore` / `macroSubjectOf` 仍被管线复用，所以整个文件不能删。
- 存量 401 条 ThesisSignal 里仍有约 300 条旧标准行，读路已滤掉，等 `backfill-signals` cron
  带 `--redo-legacy` 逐片重跑（scheduler 的 `backfill-signals` 任务未加该参数，需要时手动跑一轮）。
- `signal-log.tsx` 的 `SignalLogItem` 已被 `signal-log-list.tsx` 取代，暂留（还有单测钉着）。

# 第二轮（同日）：来源分级 + 「已验证」的硬门槛

张楚寒补了一条：

> 建议建立统一等级：1 财报/交易所公告/监管文件 · 2 公司电话会/管理层正式披露 ·
> 3 行业销量/价格/招投标/订单数据 · 4 权威媒体报道 · 5 券商研报 · 6 市场传闻/社交媒体。
> 「已验证」最好至少需要一条能够**直接支持命题**的**一级至三级**证据。
> 只有研报观点或者AI推断，最多标为「部分验证」。
>
> 建议把这个模块改名为「**逻辑追踪器：证据如何改变投资判断**」，
> 而不是简单把「最新证据」做成新闻链接。新闻可点击只是第一步，真正有产品价值的是：
> **新闻 → 客观事实 → 对应命题 → 证据强度 → 逻辑增强或削弱。**

## 落地

**`src/lib/evidence-source.ts`** — 六级分级。判定顺序从硬到软，但**传闻优先**：
一条「据传公司将扩产」哪怕挂在财联社下面也还是传闻，不能因为转载它的人体面就升一级。
两个实测出来的顺序问题：
- **② 必须排在 ① 前面**：「投资者关系活动记录表」是以公告形式披露的（source=东方财富·公告、
  tier=PRIMARY），但内容是管理层口径，按他的分级属于第二级。先判 ① 会把整类提到一级。
- **⑤ 排在 ④ 前面**：研报常由权威媒体转载，但它仍然是观点不是事实。

聚合站（东方财富·个股资讯/快讯，真库里占 9000+ 条）把真出处写在摘要开头的方括号里，
`originFromBrief` 取出来参与判级。认不出出处时**兜底给 4 不给 6**——六级留给没有编辑问责的内容，
把正规聚合站打成「传闻」是判据在撒谎，不是在保守。

**两条正交的轴**（这点很重要，别混成一个分数）：
- 来源等级 = 这条信息**有多硬**（谁说的）
- `grade` (direct/supporting) = 这条事实**是不是关于这家公司的**（说的是谁）

「已验证」＝ 两条同时成立 + 材料级 + 方向偏兑现。缺任一条 → 「部分验证」，
且 `statusWhy` 说清差在哪（来源不够硬 / 不是直接关于这家公司 / 两者都差）。
旧数据没有 sourceLevel 时按 4（媒体）+ 旁证保守处理，**不许升成已验证**。

六级（传闻/社交）在 `judgeEvidence` 里直接判废，压根不作为证据展示。

## 真库实测（406 条存量）

```
合格证据 102 条，来源等级：一级 23 / 二级 3 / 三级 12 / 四级 52 / 五级 12
其中「一至三级 + 直接支持命题」= 够格支撑「已验证」的：9 条
有证据的命题 43 个 → 部分验证 30 ｜ 已验证 4 ｜ 待验证 9
```

「已验证」从「材料度 ≥70 就给」变成 43 个命题里只有 4 个——这正是他要的效果：
这个标签现在**意味着有一条公告级的直接证据**，而不是 AI 打了个高分。
