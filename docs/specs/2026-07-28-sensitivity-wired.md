# 敏感度：从哑旋钮到真开关

> sway：「这里的敏感度调整了之后，有什么变化」→「按你推荐的做…另外，用户选择后，整个页面应立即给出反馈。」

## 调查结论：它此前几乎什么都没改变

三层问题叠在一起：

1. **只作用于一张卡的本地列表**。`personalizeSignals` 只在 `my-thesis-card.tsx` 里被 `useMemo` 调用，
   过滤「近期触及你的逻辑」。提醒中心的「投资逻辑异动」（`notifications.thesisAlerts`）
   只读 `muted` / `priority`，**从不读 `sensitivity`**；我今天做的 Outbox 推送同样没读。
2. **改了不保存**。切档只置 `dirty=true`，要按「保存」才落库——用户点完看不到任何变化。
3. **没有可作用的对象**（另一 session 同日定位）。`ThesisSignal` 全库仅 11 条 / 3 个实体，
   材料度全 <60；而阈值是 高40 / 中60 / 低80 → **中、低两档恒为 0 条**。

而 onboarding 把这个数叫 `wouldAlertCount`（「会触发提醒的数」），等于向用户承诺它管提醒。名不副实。

## 改了什么

### 1. 接进提醒（两条路径都接）

`userDimensionStatus` 扩展返回 `sensitivity` 与 `threshold`。
- `notifications.thesisAlerts`：跨越记录本身不存材料度 → **回查产生这次跨越的那条 `ThesisSignal`**
  （靠已有的 `lastCrossNewsId`，不加字段、不做迁移），低于该维度阈值的不作为提醒。
- `buildAlertEvents`（Outbox）：`CrossingInput` 加 `materiality` / `threshold`，同一道闸。
  站内 inbox 与邮件因此自然继承——**一条规则，不做站内站外两套语义**。

两处都遵守同一条兜底：**材料度取不到时放行**。数据缺失不等于「不重要」。
未采纳 thesis 的实体没有用户设置 → 阈值取最宽的 40（等同改动前行为），不凭空变严。

### 2. 即时反馈（sway 的直接要求）

- **开关类改动立即保存**：重点 / 静音 / 敏感度改用 `patchNow`，点一下即落库 +
  `router.refresh()` 刷新整页（提醒中心角标、信号条、组合视图都吃这份设置）。
  自由文本「我为什么持有」仍走显式保存——它有「还没想好」的中间态，离散选择没有。
- **逐维度实时说明**：控件旁显示 `较明确的变化就提醒（材料度 ≥ 60）· 近期 2/5 条达标`，
  切档立刻重算。让用户看得见自己在调什么、这一档在这只股上会捞到几条。
- **卡片级汇总**：`近期触及你的逻辑 · N / 共 M 条触及` + 保存后 2 秒的「已保存，全站生效」回执。
- **空态说清原因**：区分「一条信号都没有」和「有 M 条但都没过你的门槛，调到高可放宽到 40」。

### 3. 让旋钮有东西可滤（根因）

新增 `src/scripts/backfill-signals.ts`——`classify-signals.ts` 有个**全局** `MAX_NEWS=30`
上限且从没挂 cron，所以全库只攒了 11 条。新脚本按「回填三律」：幂等 / 有界分片 / 按需重排
（先自选股、再新闻多的），固定并发池。

**关键一手实测**：起初 12 条「material candidate」上 AI **只产出 1 条信号**。
分类器没坏——A 股 PRIMARY 里绝大多数是募集资金开户 / 监管协议 / 中介核查意见，
模型正确判定「不触及任何维度」。复用今天做复盘时写的 `isDigestWorthyFiling` 过滤后：
**60 条 → 25 条信号**，且材料度分布首次出现 `60-79:14`、`>=80:1`——中、低两档终于有料。

cron「解牛 逻辑信号补齐(敏感度的原料)」每 120 分钟跑一片（150 条、并发 8）。

## 顺手修的并发 bug

`written += await runJob(j)` 是**跨 await 的读-改-写**，8 个 worker 互相覆盖，
进度打出 1→3→1 的非单调数。改成先落地再累加。
（权威计数一直是 DB 前后差值，所以只是仪表盘失真，没写坏数据。）

## 遗留

`detect-crossings` 的全局门槛仍是 `MATERIAL_ALERT_THRESHOLD = 40`，所以「高」档（阈值 40）
等价于「全放行」，再往上调没有更宽的余地。要让「高」真正比「中」多捞，得把检测门槛降到 40 以下，
那会显著增加跨越记录数量——属于放量决策，未做。
